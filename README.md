# OraLink — بوابة الدخول (Landing Gateway)

صفحة هبوط واحدة، خفيفة وسريعة، تعمل **فقط** كبوابة دخول إلى موقعَي OraLink الحاليين:

| البوابة | الموقع الحالي | الجمهور |
|---|---|---|
| **OraLink Academic** | `http://localhost:3000` | الطلاب، الأطباء، رؤساء الأقسام، المشرفون، الإداريون |
| **OraLink Clinics** | `http://localhost:3001` | أطباء العيادات الخارجية |

> ⚠️ **مهم جدًا:** هذه الصفحة مشروع **مستقل تمامًا**. هي لا تلمس، ولا تعدّل، ولا تعيد نشر أيًا من الموقعين الحاليين —
> لا كود، لا مسارات (routes)، لا قاعدة بيانات، لا مصادقة، لا تهيئة، لا تنسيقات.
> لا توجد إطارات (iframes) ولا استدعاءات API ولا أي كود مشترك — فقط روابط `<a href>` عادية تخرج إلى الموقعين.
> **الشيء الوحيد الذي تغيّره هو ملفات هذا المشروع.**

---

## 1) هيكل المشروع

```
oralink-landing/
├─ index.html          الصفحة كاملة (النص العربي الافتراضي مكتوب مباشرة فيها)
├─ css/styles.css      نظام التصميم: الأزرار، الزجاج، الحركة، RTL، إمكانية الوصول
└─ js/
   ├─ config.js        ★ كل ما قد تحتاج تغييره: SITES + ROUTES + الصور + السوشيال
   ├─ i18n.js          الترجمة الإنجليزية (العربية تُستخرج تلقائيًا من index.html)
   └─ main.js          المحرك: روابط، لغة، قائمة الجوال، حركات، عدّادات
```

## 2) التشغيل محليًا (المنفذ 3002 بجانب 3000 و3001)

افتح الطرفية داخل مجلد `oralink-landing` ثم اختر أي طريقة:

```bash
# الطريقة 1 — أداة serve (موصى بها)
npx serve -l 3002

# الطريقة 2 — Node
npx http-server -p 3002

# الطريقة 3 — Python
python -m http.server 3002
```

ثم افتح: **http://localhost:3002**

بهذا تبقى المنافذ متعارضة الصفر: `3000` أكاديمي، `3001` عيادات، `3002` بوابة الدخول.

## 3) تغيير عناوين المواقع (SITES) ومسارات الأزرار (ROUTES)

كل شيء في **`js/config.js`** أعلى الملف:

```js
const SITES = {
  academic: { name: "OraLink Academic", url: "http://localhost:3000", audience: "..." },
  clinics:  { name: "OraLink Clinics",  url: "http://localhost:3001", audience: "..." }
};

const ROUTES = {
  patients: "clinics",       // بطاقة المرضى تذهب إلى بوابة العيادات حاليًا
  students: "academic",
  externalClinics: "clinics",
  heroPrimary: "academic",   // الزر الأساسي في الهيرو
  heroSecondary: "clinics",
  academicCta: "academic",
  clinicCta: "clinics",
  aiCta: "academic",         // ميزات الذكاء الاصطناعي في النظام الأكاديمي
  bookAppointment: "clinics",
  finalCtaA: "academic",     // صندوق "هل أنت مستعد للبدء؟"
  finalCtaB: "clinics"
};

const OPEN_IN_NEW_TAB = false;     // true ⇦ كل روابط المواقع تفتح في تبويب جديد
const PATIENTS_COMING_SOON = false; // true ⇦ بطاقة المرضى تعرض شارة "قريبًا" ولن تكون رابطًا
```

- لتغيير وجهة أي زر: **غيّر القيمة فقط** في `ROUTES` (مثل `patients: "academic"`) — لا حاجة لفتح `index.html`.
- كل روابط الصفحة تُبنى من `SITES + ROUTES` عبر الخاصية `data-route="..."` في الـ HTML،
  ولا يوجد أي عنوان موقع مكتوب يدويًا في أي مكان آخر.

## 4) تبديل الصور والنصوص

**الصور** — كائن `IMAGES` في `js/config.js` (كل الصور الحالية من Unsplash كأماكن مؤقتة):

```js
const IMAGES = {
  hero: "...",          // خلفية الهيرو
  pathPatients: "...",  // بطاقة المرضى
  pathStudents: "...",  // بطاقة الطلاب والأكاديميين
  pathClinics: "...",   // بطاقة العيادات الخارجية
  academic: "...",      // صورة قسم الطلاب
  clinic: "...",        // صورة قسم العيادات
  xray1: "...", xray2: "..." // صورتا الأشعة داخل بطاقة الذكاء الاصطناعي
};
```

غيّر الرابط فقط، ويفضل استخدام روابط مباشرة بمقاسات جاهزة مثل
`https://images.unsplash.com/photo-XXXX?auto=format&fit=crop&w=1400&q=80`.
(لا تنسَ أيضًا تحديث `og:image` في `<head>` من `index.html` عند تبديل صورة الهيرو.)

**النصوص** — الصفحة ثنائية اللغة (عربي ⇄ إنجليكي) مع زر تبديل في الشريط العلوي:

- **العربية (اللغة الافتراضي):** عدّلها مباشرة داخل `index.html` — النص العربي مكتوب في مكانه.
- **الإنجليزية:** عدّلها في `js/i18n.js`. المفتاح (key) مكتوب على كل عنصر في الـ HTML
  مثل `data-i18n="hero.title1"`، فستجد نفس المفتاح في `i18n.js`.
- الاتجاه `dir` والخاصية `lang` والخط (Cairo للعربي، Inter للإنجليزي) تتبدّل تلقائيًا،
  وتُحفظ اختيارك في `localStorage`.
- الروابط الاجتماعية في الفوتر تُضبط من كائن `SOCIAL` في `js/config.js`
  (استبدل الروابط المؤقتة بحساباتك الحقيقية).

## 5) استبدال localhost بالعناوين الحقيقية عند النشر

في `js/config.js` فقط:

```js
const SITES = {
  academic: { name: "OraLink Academic", url: "https://academic.yourdomain.com", audience: "..." },
  clinics:  { name: "OraLink Clinics",  url: "https://clinics.yourdomain.com",  audience: "..." }
};
```

كل الأزرار والبطاقات ستُعاد توجيهها فورًا — لا يوجد أي رابط صلب في الصفحة.

## 6) النشر المجاني

المشروع ملفات ثابتة (HTML/CSS/JS) — ارفعه كما هو بلا أي إعداد خادم.

**Netlify (الأسهل):**
1. افتح <https://app.netlify.com/drop> واسحب مجلد `oralink-landing`.
2. ستحصل على رابط مثل `https://اسم-عشوائي.netlify.app`.
3. لاحقًا: **Domain settings → Add domain** لإضافة نطاقك، واتبع تعليمات DNS لدي مزوّد النطاق.

**Vercel:**
```bash
npm i -g vercel
vercel --prod
```
ثم `Settings → Domains` لإضافة نطاقك.

**GitHub Pages:**
1. أنشئ مستودعًا وارفع الملفات.
2. `Settings → Pages → Deploy from a branch` واختر `main` / مجلد الجذر.
3. سيعمل على `https://<اسم-المستودع>.github.io/oralink-landing/`.
   (ارفع الملفات في الجذر المستودع نفسه إن أردت رابطًا على النطاق الرئيسي.)

**قبل النشر الفعلي:** غيّر `SITES` إلى عناوين الموقعين الحقيقيين (الخطوة 5)،
و `SOCIAL` إلى روابطك، وصورة `og:image` إلى صورة مستضافة لديك.

> ملاحظة: الصفحة تستخدم Tailwind عبر CDN للاختصار. إن أردت إنتاجًا نهائيًا أكثر نظافة،
> يمكنك لاحقًا بناء Tailwind محليًا — لكن ذلك لا يُشترط.

## 7) تذكير أخير

الموقعان الحاليان (3000 و3001) **لم يُمسّا بأي شكل** — لا كود، لا مسارات، لا قاعدة بيانات،
لا مصادقة، لا تهيئة، لا تنسيقات. هذه البوابة فقط روابط خارجية تشير إليهما،
ويمكن حذفها أو نقلها في أي وقت دون أي أثر عليها.
